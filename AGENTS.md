# Project documentation

Keep `FILE_GUIDE.md` updated alongside every code change. Finish the guide update as part of the same task, so its explanation matches the code the user is reading.

- Use plain, understandable language. Explain technical terms when they first appear.
- For each new or changed file, explain its purpose and how it connects to the rest of the application.
- Explain the main functions, their inputs, and their outputs. Use a small example when it helps.
- Describe what new tests check in everyday language.
- Keep the phase history in `FILE_GUIDE.md` current: explain what was built in each phase, which files changed, what became possible, and how it was checked.
- Clearly distinguish working features from steps planned for a later phase.
- Keep code comments helpful for a reader learning the project.
